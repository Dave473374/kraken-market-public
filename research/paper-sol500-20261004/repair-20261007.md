## Deployed repair

Workflow activation commit: `6c73be6bb815c1d8f8b7a4d84e2735b5e9415fc8`.

- New `reliable_runner.py` wraps only operational publication, recovery and successor management. It does not calculate trading signals.
- Git fetch/push transport failures receive bounded, progressively spaced retries instead of three immediate attempts. History conflicts and access failures fail closed; there is no force push, reset or rebase.
- Publication retries the same local commit, including when it has already been committed and the staging area is empty. No subsequent engine evaluation is allowed with unpublished work.
- At handoff, including after an operational failure, the queue is checked again. A historical `ACCEPTED` receipt is not treated as proof that its successor still exists or started.
- Before normal evaluations, completed failed runs of this same workflow are checked for recovery artifacts. Complete, matching original records can be restored; incomplete evidence with an unpublished financial change stops recovery rather than inventing fills.
- Future failure artifacts include original observation files, not only the three summary JSON files. No `.git` directory or credentials is uploaded.
- The original single-writer concurrency lock and backup schedule remain. Job timeout includes room for bounded retries; it does not extend the trading period.
